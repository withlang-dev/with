## v0.16.0.5

v0.16.0.4 was published for darwin-aarch64, linux-x86_64, linux-aarch64 and
windows-x86_64, each with its SDK. Its windows-aarch64 release lane, which
only CI builds, was red, and so was every other CI lane, while each test
passed on every warm host: the lanes' captures named fixed time ceilings and
a missing host package, not compiler bugs. v0.16.0.5 is those fixes, released
for every platform (D180).

- **Every test ceiling is a hang guard, not a speed budget (#2902).** The
  selfhost cases' 190 child ceilings of 10 s to 10 min, the complexity
  battery's compile and timing runs, three behavior tests and the build.w
  test runner's own 300 s all become the thirty-minute guard; a test lane as
  a whole has an hour. A 4-core release runner under a full battery had
  crossed each of them with a passing test, and one fixture's distinctive
  `.timeout(12345)` was also its seven child compiles' budget.
- **The complexity battery takes the least of three samples (#2911).** Load
  only adds to a sample, and the median had read a linear priority queue at
  6.3× for n×4 under the battery's load.
- **The linux-x86_64 release lane installs the facade tests' host headers**
  (`bzlib.h`, `sqlite3.h`, `curl/curl.h`), as the linux-aarch64 lane always
  did; a red battery's captures include the build-runner tests' per-case
  output.

## v0.16.0.4

v0.16.0.3 was published for darwin-aarch64, linux-x86_64, linux-aarch64 and
windows-x86_64, each with its SDK; windows-aarch64, which only the CI lane
builds, failed its tests there on a fixed 300 s per-test ceiling in the seed
that drives the lane. v0.16.0.4 is built by a new seed carrying the
thirty-minute hang guard and is released for every platform (D180).

- **The complexity battery measures in clock ticks (#2894).** A sample now
  spans at least 20 ticks of the CPU clock; Windows's 15.6 ms tick had put a
  tick of error into each run and failed a linear row at random under load.
- **linux-aarch64 has a package target**, and `:package-current-host` names
  the host's own target: a host no platform names fails by name instead of
  packaging for another platform.

## v0.16.0.3

v0.16.0.2 was published for darwin-aarch64, linux-x86_64 and windows-x86_64;
its linux-aarch64 release UAT and its windows-aarch64 release lane were red.
v0.16.0.3 is those fixes, released for every platform (D180: each with its
SDK).

- **`with cc` on Linux finds the host's headers.** It compiles against the
  SDK's own libc (`--sysroot`), and a header the SDK does not carry
  (`X11/Xlib.h`) was not found even with the host's development package
  installed. It now searches the host's include directories after every
  SDK directory, as `c_import` always did, so a `with get` source build
  against a system package (glfw against xorg/system, where Conan Center
  has no binary) compiles.
- **A capture that times out on Windows stops the whole process tree.**
  Every child the runtime spawns runs in a job object of its own; the
  timeout terminates the job, as the POSIX runtimes kill the child's
  process group. Before, the direct child alone was terminated and its
  children ran on.
- **Test lanes keep a hang guard, not a speed budget.** The debug-alloc
  lane, the build-graph test lanes and `with test`'s check step used fixed
  60 s and 300 s ceilings that failed passing tests on a slow machine
  (#2362); each now uses the thirty-minute hang guard, and names it.

## v0.16.0.2

v0.16.0.1 was published for darwin-aarch64, linux-x86_64 and windows-x86_64;
v0.16.0.2 was published for the same three (linux-aarch64 and windows-aarch64
follow in v0.16.0.3, D180: each with its SDK). The linux-aarch64 battery was
red on the platform itself until now: the tests spelled C's `char` as
`*const i8`, and `char` is unsigned there. One user-visible change comes with
that: a facade diagnostic and a `with analyze … contract` view now print a C
parameter as the header spells it (`*const c_char`), never its resolved width
(§57).

## v0.16.0.1

v0.16.0.0 was published for darwin-aarch64 and linux-x86_64 only: its Windows

## v0.16.0: the largest With release yet

1011 commits since v0.15.2.1 (2026-09-06), 87 rulings (D93 through D179)
in the decision log, every one landed in the compiler, the runtime and the
standard library before this tag. The number stays humble (0.16, not 1.0):
rulings still change the surface weekly, and the spec leads a compiler it
still calls non-compliant in places (D51 modeled C, §4.8). What changed, by
what a program sees.

### Ownership and values

- **Copy-or-move is decided by identity, not representation (D111).** Values
  (integers, floats, `str`, keys) copy; resources (files, tasks, sockets,
  handles) transfer. `str` is a value: an immutable shared buffer with an
  atomic count. Code using `str` never sees "use of moved value" and never
  writes `.clone()`.
- **A parameter's mode is what the callee does with it (D110).** `get`,
  `contains` and `remove` observe their key; `insert` takes it. Builtin modes
  come from declared signatures, nowhere else.
- **Collections and structs of values are values (D120).** Copy-on-write
  with an atomic count; a `Drop` impl, a resource field or `resource type`
  makes a resource.
- **A collection's copy class is part of its interface (D152).** `List`,
  `HashMap` and `HashSet` copy with a count. **`BTreeMap` and `BTreeSet` are
  now resources** (facades over the M*LIB B+tree, D151): `var n = m` moves
  the map, a copy is `m.clone()` (O(n)), and the moved-value diagnostic says
  so.
- **Mutation is a declared capability on any parameter: `mut p: T` (D172).**
  Exclusive access begins when the call does; a `mut fn` call mutates the
  field paths its body writes, at full depth within a package (D178).
  Read-path caches are the sealed std type `Memo[K, V]` (`std.memo`, D176).
- **Bindings observe places (D144, D174, D179).** A binding from a place of a
  plain-bits type takes the value; any other binding observes. A view that
  cannot outlive its statement takes an independent value; an unannotated
  binding of a view of `str` takes the `str`.
- `let _` drops (D95); `++` concatenates sequences and observes its operands,
  `++=` extends in place (D116); `first()`, `last()`, `rest()` are the
  expression forms of `[first, ..rest]` (D117).

### Types and inference

- **`isize` is the target's size width; unsuffixed integers default to it
  (D114).** `len()`, `count()` and `position()` return `isize` (D108). No
  code assumes a width: supported targets are 64-bit hosts and wasm32.
- **An integer in a boolean-test context is true when nonzero (D177)**; there
  is no other conversion between `bool` and integers (`c as i32` is 1 or 0).
- **Brackets make a `List`** unless a fixed array or a set is demanded
  (D113, D118: `Vec` names no type). A collection literal's binding takes its
  type from its uses (D93).
- **Untyped constants have no width until a context types them (D124,
  D125, D128, D160)**; a slice demand types a literal argument (D126); a
  distinct type over a number takes an unsuffixed literal (D153).
- **A function that calls itself infers its return from the paths that do
  not (D143)**; an inferred return joins `None` with `T` into `Option[T]`
  (D141); a value converts to `Option[T]` once, at the demand (D103).
- Impl methods take their signature from the trait (D140); a trait names its
  method `Trait.method(args)` (D169); a `Drop` impl's bounds are the type's
  own (D154).
- `str.parse` (D165) and `std.random` (D162) produce the type their use
  demands.

### Syntax and resolution

- **A match arm is `pattern [if guard] => body`** (D163); the body takes the
  three forms after `=>`.
- **A name resolves lexically, once (D173)**: a local shadows a
  module-scope function for every use; calling a non-callable local is an
  error, never a fallback. Visibility is package-wide: `pub` leaves the
  package, `internal` stays inside (D100). The last import wins a namespace
  (D70); a header's `extern var` keeps its name and a With value sharing it
  is displaced by import order (§18.2).
- **Operators serve their own side (D166, D167)**: only `==`/`!=` dispatch
  from the right; a scalar on the left is an extension method of the
  scalar's type.
- An implicit `it` closure is the nearest enclosing single-parameter
  function argument (D161). `|>` iterates a sequence by the `for` rule
  (D142); a `List`'s adapters are its iterator's, there is no eager
  `List.map` (D168). Ranges have `iter()`, `start` and `end` (D145); a range
  over `str` is refused (§4.7).
- Runtime globals initialize in dependency order, transitively; cycles are
  errors (D175).

### C interop

- **`with get` builds a package's facade from evidence, strongest first
  (D121, D122)**: proof from the library's source, shipped annotations, the
  shared registry (`registry/c/<package>/facts.w`, D136), adopted profiles.
  The proof engine is `with migrate --facade NAME` (D133).
- **`extern "C" fn` is non-null; a nullable C function pointer is an
  `Option` placed by direction (D102, D107).** `T.zeroed()` is safe on
  zero-valid C records (D101).
- **A migrated corpus is compiled against one explicit data model (D155,
  D156)**: fixed integer widths, only `c_char` symbolic. Bitfields keep C's
  layout (D147). A `static inline` a header defines is published by its sole
  includer (D150).
- The migrator emits a safe signature where a function's body proves its
  contract (D159), and is a pinned input of each corpus (D112).
- `std.mssql` is deferred past this release (D123, #2458).

### Standard library

- The engine corpora live under `std.engines`; facades are named for their
  function, engines for their provenance (D146). `std.regex` is a facade over
  the migrated pcre2 bundle (D38, D39).
- `LinkedList`, `Stack`, `Queue`, `SortedList`, `BinaryHeap`, `Trie`,
  `HashIndex` and the unordered map and set are sourced from migrated
  corpora (D148, D149, D157). `List[T]` stays the runtime's.
- `std.encoding.xml` is a strict native tree reader (D135). `str.rfind`,
  `trim_start`/`trim_end`, `bytes()` (D105), `str.find(needle, from)` (D129).
- `with_concurrency(inputs, n, f) -> List[T]` starts the work itself (D164).
- Maps are seeded and iterate in insertion order; a key is any structurally
  comparable value (D96, D97).
- A new prelude function or intrinsic can break a bare use in a user type
  with a same-named field; the fix is `self.name` (or `builtins.name`).

### Toolchain

- **The runtime is a bundle (D30)**: `rt/*.w` compiled as one unit per
  compiler generation and target, embedded in the compiler; the standard
  library imports its interface. A runtime of another generation is never
  linked (D132).
- **`.wo` bundles are durable (D138)**: rebuilt when their sources or
  imported contracts change, never because the compiler did.
- Validation is scoped to its tier (D131): a fix, a PR, a seed cut or a
  release. Migration runs at a seed cut or release, or when a human asks.
- `--emit-c` emits what the program reaches, `--emit-all` everything (D130).
- Comptime-callability is inferred; the witness chain is the diagnostic
  (D104). `with analyze` gained `audit:resolution` (D65: one owner per fact).
- The compiler, its runtime and its build are bootstrapped from our own
  sources and SDK and call no host tool; a user's own build may (D171).
- The ceremony census (`tools/ceremony_census.w`) gates every PR: a count
  that rises fails. This release retired `if c: 1 else: 0` and the
  compiler's integer-returning predicates (#2857).
- windows-aarch64 is published but non-gating (D137).
