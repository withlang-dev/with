With is an ergonomics-first systems language: close to the machine, native by default, exactly as safe as Rust, and built to remove the suffering.

Every character the program has already determined is a compiler failure if the programmer still has to write it. When exactly one meaning is forced — by types, by scope, by a header, by an ABI, by a proof — With infers it, imports it, fetches it, binds it, proves it, generates it, links it, migrates it, wraps it, or makes it safe. When two meanings remain, the programmer spells the choice. That spelling is a guardrail, not ceremony. A documented default may stand in for the choice only when the alternatives are representations of the same meaning (an unsuffixed `1` is `i32` unless context says otherwise); a default never selects between meanings.

C interop is first-class, not an escape hatch. With should understand C headers, ABIs, native libraries, linkers, package managers, and existing C code well enough to import, integrate, and migrate them without making the programmer become the build system.

With pays compiler complexity to remove ceremony without removing guardrails. Raw C stays explicit; modeled C becomes humane. The goal is native control, Rust-level safety, and C-level reach — with the suffering automated away.

The language is named for the `with` scope: a resource lives in its scope and is released when the scope ends. Memory is the first resource, not an exception. Every allocation is owned from the moment it is made, and its owner's scope releases it — the compiler proves this the same way it proves safety. Here With is stricter than Rust: Rust calls leaking safe; With calls it a defect. Leaking memory must take deliberate, visible effort — a programmer who wants a leak has to spell it out. If the creators of the language can leak by accident, the design is wrong, not the programmer.

## Laws

The decisions in `docs/meetings/README.md` are instances of a small number of laws. A new decision is tested against them before it is ruled: it is an instance of one, or it names the new law it needs. Each law carries its test, the question that decides a case, and the decisions that already fall out of it.

**1. The compiler never asks for what it already knows.** One meaning forced, the compiler supplies it; two meanings remaining, the programmer spells the choice, and that spelling is a guardrail; a default picks a representation, never a meaning. *Test: does this make the programmer state something the compiler can establish, or something with no consequence?* (D43 tail inference, D93 collection literals by use, D103 value to Option, inferred return types, no `Ok(())`, no `let _ =`, the ceremony gate.)

**2. Demand propagation is one mechanism, not a family of conveniences.** A type demanded at a site flows into the expression at that site, in two phases and one order. A demand first binds the unknowns the expression's own signature leaves open; conversions then apply between two known types and never bind an unknown. An expression's own operands bind before the outer demand fills what remains. The expression takes the demanded type when it has exactly one way to, and nothing applies where nothing is demanded. *Test: is this "the compiler figures X out from context" written as an instance of this law, with both guardrails and the order?* (Numeric literals §4.2.1, a generic result parameter from the demand, D93, D103, field types from defaults, variant shorthand: five features, one rule. `let x: Option[i32] = make()` binds `T` — phase one; `let x: Option[i32] = 3` converts — phase two; `first(3)` against `Option[T]` is an error — no conversion in phase one, no demand known for phase two. `let x: Option[i32] = ident(3)` is `Some(ident(3))`, never `ident(Some(3))`: the operand binds `T := i32` before the demand fills the rest, so a demand never changes a generic's instantiation and "once, at the demand" is literally the outermost point. "Exactly one way" is why `Option[Option[T]]` is refused; "a conversion never binds an unknown" is what keeps With off Swift's overload cliff.)

**3. One owner per fact.** Sema decides what; MIR decides where and when; codegen decides how. A downstream stage may propagate, materialize and verify a fact; it never reconstructs or overrides one. *Test: if deleting this downstream code could change which programs are accepted, the boundary is wrong.* (D65, D6 `FnAbi` computed once, D97 operand types, `audit:resolution`, the retirement of name-based decisions in MIR, a validator that stays silent is a bug.)

**4. A fact is inferred only when being wrong cannot create unsafety.** Infer what at worst removes capability or rejects a valid program; never infer what could grant ownership, destruction, retention, independence, static lifetime, success, thread crossing, or a null the type forbids. Those come from a declaration, a proof, or an adopted profile, never from a name. *Test: what happens if this inference is wrong?* (D51's asymmetry rule, D101 zero-validity by structure, D102 nullability by direction with `nullable param N` as the explicit widening, no safe constructor without a destruction contract.)

**5. Observing is not owning; transport is not duplication.** Access to a place observes it; `remove`, `drain`, `into_*` and a consuming signature transfer; the compiler moves bytes but never manufactures a second live value of a non-`Copy` type; a lost borrow origin is a bug, not a convenience. *Test: does this operation create an owner the type system does not know about?* (D22 map views, D27 element places and no positional `get`, D44 map traversal, D5 the signature states ownership mode, D52 globals are never moved out, D72/D82 the liveness byte and vacate-then-drop, no implicit copy unless O(1).)

**6. The signature is the contract; the body is evidence about the body only.** A declaration states its parameter modes, effects and visibility independently of its current implementation; what a body happens to do never silently changes a public contract. Inside, where nothing is promised to anyone, the compiler infers freely. *Test: is the programmer promising something to a reader who cannot see the body? Then spell it. Otherwise never.* (D5 no borrow inferred from a read-only `T`, D39 bundle global writes declared rather than inferred into the interface, D100 `pub` is the promise that leaves the package and nothing is written inside it, D104 `comptime fn` is the promise while a plain function is judged when reached.)

**7. Fail loudly or do the work; never produce a plausible wrong thing.** No placeholder bodies, no silent stubs, no `-O0` to go green, no editing the user's program to make a rule pass, no weakening a check. A migrator at 30 of 30 with stubs is worse than 0 of 30 with an error. *Test: did I make the success condition true by doing the work, or by redefining it?* (Codegen reports `BUG:` instead of emitting `undef`, the UAT contract, "pre-existing" requires evidence, D56 the battery is the gate and CI is not a signal, a drift check that refuses a hand-edited corpus.)

**8. The toolchain absorbs the environment, within a boundary.** A build reads only our SDK; a program needs only the OS; the seed is pinned and drives the battery; corpora are generated, never hand-edited. The boundary is what makes an ordinary native build deterministic and humane, never every tool anyone might need. *Test: does carrying this remove an environmental dependency from an ordinary build, or does it just add a tool?* (D30 in-unit runtime and no mixed-generation links, D49/D50 a green keyed to inputs, zero dependencies, embedded clang headers, the no-host-toolchain gate.)

**9. Delete the old route once the better one exists.** Two spellings of one meaning are a defect; an escape hatch that outlives its reason is a defect. *Test: is this route still the unique way to say something, or a habit?* (D71 `Vec.get` retired for indexing, D30 the `with_*` seam, the fallback switch codegen no longer has, Python out of the benchmark runner, migrators removed rather than kept in case.)

**10. The mission is tested, not described.** Every principle has an adversarial program that must keep passing: the ceremony gate, the one-liner parity matrix, the C corpora and their drift check, the user-programs-safe gate, the drop and move audits, the emit-C self-build, the no-host-toolchain run. *Test: what program would fail if this rule were quietly lost? If there is none, write it before the rule lands.*

Law 1 is the purpose. Law 2 is the one mechanism that delivers most of it safely. Laws 3 and 6 say where a fact lives: which stage, and interface against body. Laws 4 and 5 say what may be inferred about resources, the two places where being wrong is unsafe. Laws 7, 9 and 10 are the discipline that keeps the implementation honest about the first six, and law 8 is that discipline applied to the environment. A proposal that needs an eleventh law is allowed; it says so, and the law is written here before the decision is.
