## Findings
1. src/compiler/EmbeddedClangResource.w:60-65 — Severity: low — Targets:
   T22 — Probe status: static trace vs callers (probes 1-2 pass; no runtime
   failure injection). `ensure_clang_resource_dir` discards all I/O results
   (`let _mk`, `let _w`, `let _stamp`) yet always returns a non-empty root,
   which `ci_prepare_clang_resource_dir` (CImport.w:277-280) forwards to
   `with_cimport_set_resource_dir` on a `len() > 0` check alone. A read-only
   or full `$XDG_CACHE_HOME` therefore yields a silent partial resource dir
   instead of a clear error. Refutation attempt: stamp-last discipline means a
   failed run writes no stamp, so the next compile retries rather than trusting
   a partial cache — self-healing, and failures surface as downstream libclang
   parse errors. Survives as a robustness gap only, not a correctness defect.
2. src/compiler/Frontend.w:310-311 (comment about this module) — Severity:
   info — Targets: T22 — Probe status: confirmed by negative-control grep
   (probe 4). The comment claims the `ensure_clang_resource_dir()` call "keeps
   the materializer in the compile graph for the bridge's
   `with_ensure_clang_resource_dir` extern", but no such extern is declared in
   `src/compiler/ClangBridge.w` (extern list at ClangBridge.w:8-28,68+) or
   anywhere in `src/`/`build/`. Stale comment; the call itself is still
   required (it runs before `with_cimport_parse`). Refutation attempt:
   searched native side too — `with_ensure_clang_resource_dir` matches nothing
   outside the comment. Comment-only, no behavior impact.
