# D147 — A migrated record with bitfields keeps C's layout: storage units under `@[repr(C)]`, accessors per member, stores that truncate as C does, one layout for every target or a loud refusal (#2553)

**Date:** 2026-10-22. **Status:** ruled by Eric ("Bless it"). The brief is
on #2553; the five points below are his words and are normative.

## Eric's ruling

> Bless it. Clang's layout is the right authority, the bit arithmetic is
> what C compiles to anyway, and the D51 test passes. Five things need
> settling before it lands, the first two because they change what the
> migrated code means.
>
> **1. The layout is clang's for one target, and the migrated file is
> compiled for all of them.** Itanium and MSVC agree on STC's records,
> because each unit's members share one declared type and size. They
> disagree in general: MSVC starts a new storage unit when the declared type
> changes (`int a:3; char b:2`), and Itanium packs across. A migration run
> on macOS would emit offsets that are silently wrong on Windows, and since
> D38 compiles migrated corpora once into bundles, nothing would re-derive
> them. The migrator should ask clang for the layout under every supported
> target triple, emit the record if they all agree, and refuse loudly,
> naming the record and the two targets, if they don't. Also emit
> `comptime` assertions of each record's size and each unit's offset, so a
> disagreement surfaces when the file is built, not when the upstream tests
> happen to probe it.
>
> **2. Writes must truncate as C does, not obey With's overflow rule.**
> `m->dist++` at 1023 wraps to 0 in C. If the lowering is `set(get() + 1)`
> in ordinary With arithmetic under the default `overflow = "panic"`, the
> migrated program panics where the C one didn't. State that a bitfield
> store masks the value to its width (unsigned modulo 2ⁿ; for signed
> members, clang's two's-complement truncation), and that the
> read-modify-write is the faithful lowering whatever the project's
> overflow setting.
>
> **3. Emit accessors, not inline shifts at every use.** Rewriting each
> `m->dist` into a shift-and-mask expression makes the output unreadable and
> every bug a puzzle. Generate a getter and setter per member on the record,
> as bindgen does, and lower member access and compound assignment to calls
> on them. It's still raw and faithful, the debugger shows a name, and it is
> exactly the surface a facade or a later `c_import` can present without
> regenerating anything.
>
> **4. Pin the storage-unit rule for the awkward cases.** For STC, "one
> field of the declared integer type" works. In general a unit can mix
> signedness (`int32_t spawn_count:24` next to `uint32_t on_error:7`), and a
> packed record can put a unit at an unaligned offset. Make the storage an
> unsigned integer of the unit's size (signedness belongs to each member's
> extraction), and refuse loudly anything clang lays out that isn't a whole
> aligned integer unit, rather than guessing. Also say what happens to:
> - **unnamed and zero-width bitfields**: padding and alignment only, no
>   member;
> - **enum-typed bitfields**: if C enums import as With enums, a 3-bit read
>   can produce a value no variant has. The getter must return the integer,
>   or a checked conversion, never an unchecked enum;
> - **`volatile` bitfields**: refuse; a read-modify-write can't be made
>   faithful to them.
>
> **5. Decide `c_import` deliberately rather than by omission.** After this
> lands, a migrated STC can use `hmap_meta` while `c_import` of the same STC
> header still sees it opaque. That's fine for Phase 3, but if the accessors
> from point 3 are generated by shared code, `c_import` can adopt them with
> a one-line spec change instead of a second design. I'd keep §16.9's
> sentence for now and add a note that the migrator's representation is the
> intended one for both.
>
> One correction to the brief: "a width or offset read wrong is a migration
> that fails its upstream tests loudly" holds only for fields the tests
> exercise, and only on the target that ran the migration. Point 1's
> per-target check and the size assertions are what make the answer to
> D51's test genuinely "nothing".

## The implementation this fixes

The migrator (`with migrate`): a record with bitfields is no longer demoted
to opaque. Its bitfield members group into storage units, each an unsigned
integer of the unit's size (`__bits_<n>`) under `@[repr(C)]` at clang's
offset; a getter and a setter per named member; member reads, assignments,
compound assignments and `++`/`--` lower to the accessors; the setter masks
to the width (a signed member two's-complement truncates); `&m->field` is
refused as C refuses it. The per-target agreement is checked without a second
parse: Itanium and MSVC agree exactly when no unit holds members of
differing declared size and every unit is a whole aligned integer, which the
migrator verifies from clang's layout and otherwise refuses, naming the
record and the two ABIs; `comptime` assertions of the record's size and
every unit's offset are emitted beside the record. Unnamed and zero-width
members get no accessor; an enum-typed member's getter returns the integer;
a `volatile` bitfield is refused. `c_import` keeps §16.9's sentence; the
spec notes the migrator's representation is the intended one for both.
